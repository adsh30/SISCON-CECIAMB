Instalar SISCON-CECIAMB en otra PC

Paso a paso para tener el sistema funcionando en otra computadora, con los mismos datos (usuarios, plan de cuentas, comprobantes) que la PC donde ya se usa.

⏱ Tiempo30 a 45 minutos la primera vez
💻 SistemaWindows 10 u 11, con internet
📁 NecesitaEl archivo .sql con la copia de la base de datos
Dos computadoras: la PC de origen es la que ya tiene el sistema con los datos; la PC nueva es donde se va a instalar. Todos los comandos se escriben en PowerShell (menú Inicio → escriba «PowerShell» → Enter).

Parte 1 · Sacar la copia de los datos

  1. PC de origen

    Exportar la base de datos

    Abra PowerShell en la carpeta del proyecto y ejecute:

    cd $HOME\Documents\GitHub\SISCON-CECIAMB npm run bd:exportar

    Al terminar dice Copia creada: respaldos\siscon_db-AAAA-MM-DD-HHMM.sql. Ese archivo es la copia completa: usuarios, datos de la empresa con su logo, plan de cuentas, comprobantes y tasas.

    Ese archivo es confidencial. Lleva los usuarios con sus claves cifradas y los datos del hospital. Páselo solo por USB, carpeta compartida de la red o Drive con acceso restringido. Nunca por grupos de WhatsApp ni subido a GitHub.

    Consejo: si la persona de la PC nueva va a entrar con su propio usuario, créelo antes en Usuarios y roles → Agregar usuario y luego exporte.

Parte 2 · Preparar la PC nueva

  1. PC nueva

    Instalar los 3 programas (una sola vez)

    ProgramaDóndeAtención
    Node.js 24 o superior nodejs.org Siguiente, siguiente, finalizar.
    Git git-scm.com Deje las opciones que trae.
    MariaDB 11.8 o superior mariadb.org/download Le pide una clave para root: anótela, se usa en el paso 4.

    Después de instalarlos, cierre y vuelva a abrir PowerShell.

  2. PC nueva

    Descargar el sistema

    El repositorio es privado: el dueño debe agregar su cuenta de GitHub en adsh30/SISCON-CECIAMB → Settings → Collaborators. Luego:

    cd $HOME\Documents git clone https://github.com/adsh30/SISCON-CECIAMB.git cd SISCON-CECIAMB git checkout dev npm install

    La primera vez Git puede abrir una ventana para iniciar sesión en GitHub.

  3. PC nueva

    Crear la clave secreta

    Este comando genera una cadena larga al azar. Cópiela; se usa en el paso siguiente:

    node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
  4. PC nueva

    Configurar el archivo .env

    copy .env.example .env notepad .env

    En el Bloc de notas complete estas líneas y guarde (Ctrl + S):

    LíneaQué poner
    DB_PASSWORD=Una clave que usted invente para la base de datos del sistema.
    DB_ROOT_PASSWORD=La clave de root que anotó al instalar MariaDB.
    JWT_SECRET=La cadena larga del paso 3.
    MARIADB_DUMP= Solo si instaló otra versión de MariaDB: cambie MariaDB 13.0 por la suya (mire el nombre de la carpeta en C:\Program Files).

    Las demás líneas se dejan como están.

  5. PC nueva

    Cargar la base de datos (un solo comando)

    Copie el archivo .sql de la Parte 1 dentro de la carpeta respaldos del proyecto (si no existe, créela) y ejecute, con el nombre real de su archivo:

    npm run bd:preparar -- respaldos\siscon_db-2026-10-10-1711.sql

    Este comando lo hace todo solo:

    • crea la base de datos del sistema y la de pruebas;
    • crea el usuario de MariaDB con la clave de DB_PASSWORD;
    • carga la copia;
    • la pone al día si el sistema es más nuevo que la copia.
    Termina con «Listo: la base tiene los mismos datos que la copia».
  6. PC nueva

    Encender el sistema

    npm run dev

    Deje esa ventana de PowerShell abierta mientras use el sistema. Abra Chrome o Edge en:

    http://localhost:5173
    Entre con el mismo correo y la misma clave que usa en la PC de origen. Verá los mismos datos.

    Para apagarlo: en PowerShell pulse Ctrl + C. Para volver a encenderlo otro día:

    cd $HOME\Documents\SISCON-CECIAMB npm run dev

Parte 3 · Después de instalado

  1. PC nueva

    Traer la última versión del sistema

    Cuando haya cambios nuevos (apague antes con Ctrl + C):

    git pull npm install npm run db:migrate npm run dev
  2. PC de origen PC nueva

    Volver a copiar los datos

    Cada PC tiene su propia base: lo que se registra en una no aparece en la otra. Para traer de nuevo los datos de la PC de origen, repita la Parte 1 y en la PC nueva ejecute:

    npm run bd:importar -- respaldos\ARCHIVO-NUEVO.sql --reemplazar
    --reemplazar borra lo que había en la PC nueva y deja solo la copia.
¿Solo necesita usar el sistema, no tener una copia aparte? No instale nada: desde otra PC de la misma red abra en el navegador http://IP-DEL-SERVIDOR:8080 (o :5173 si el servidor está en modo desarrollo). Así todos trabajan sobre los mismos datos. La IP se ve con ipconfig en el equipo servidor.

Si algo sale mal

MensajeQué hacer
npm o git «no se reconoce»Cierre y abra PowerShell de nuevo. Si sigue, reinstale Node.js o Git.
Falta DB_ROOT_PASSWORDComplete esa línea del .env (paso 4).
Access denied for user 'root'La clave de root del .env no es la que puso al instalar MariaDB.
Access denied for user 'siscon_app'Cambió DB_PASSWORD: ejecute npm run bd:crear para igualarla.
No se encontró mariadb.exeCorrija MARIADB_DUMP en el .env con la carpeta de su versión de MariaDB.
La base siscon_db ya tiene … tablasYa había datos. Para reemplazarlos use npm run bd:importar -- respaldos\archivo.sql --reemplazar.
No existe el archivoRevise que el .sql esté en la carpeta respaldos y que el nombre esté bien escrito.
La página dice «Sin conexión con el sistema»Se cerró la ventana de PowerShell o se detuvo: vuelva a ejecutar npm run dev.
No abre localhost:5173Espere unos segundos tras npm run dev y recargue con F5.
